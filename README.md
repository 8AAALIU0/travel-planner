# travel-planner
# 山海之间 · 个性化旅游规划系统

基于 Python 与 Django 开发的旅游规划网站，也是 Python 程序设计课程项目。

用户可以输入出发城市、目的地、旅行日期、天数、人数、总预算和兴趣偏好，查询旅行相关信息，生成包含每日景点、交通、住宿参考及费用汇总的旅行方案。

## 在线体验

[进入山海之间旅游规划网站](https://travel-planner-alns.onrender.com/journey/)

使用流程：

1. 填写出发地、目的地、日期、天数、人数及预算。
2. 选择兴趣标签、交通偏好和住宿条件。
3. 点击生成旅行方案，等待分阶段查询完成。
4. 查看每日行程、路线信息、费用及查询提示。
5. 根据需要调整条件或导出方案。

## 主要功能

- 景点检索：按城市和兴趣关键词获取、筛选景点。
- 多日行程规划：结合游玩时长、开放时间和通勤安排景点。
- 往返交通查询：查询交通候选，比较价格、时刻与可游玩时间。
- 住宿参考：根据日期、预算和位置偏好查询酒店。
- 预算核算：汇总交通、住宿、门票、餐饮、市内交通及备用金。
- 路线展示：提供每日路线信息和地图查看入口。
- 方案导出：保存规划结果，便于查看与分析。
- 状态说明：展示接口异常、报价缺失和方案待确认项目。

## 技术方案

- 开发语言：Python
- Web 框架：Django
- 本地数据库：SQLite
- 云端数据库：PostgreSQL
- 页面技术：HTML、CSS、JavaScript
- 地点与路线服务：高德开放平台
- 交通、酒店及部分门票查询：途牛接口
- 优化建模：PuLP / CBC
- 部署方式：Docker、Gunicorn、Render

## 规划算法

系统先整理用户需求与查询数据，再筛选景点和往返交通候选。

日程生成结合束搜索、局部改进和日路径整数规划，在预算、可游玩时间、景点开放时间及重复访问等约束下选择行程，并对最终方案进行核验。

通过有效缓存、批量读取和步骤内结果复用，减少重复查询与计算。

优化范围受候选数据、保留路径数量和求解时间限制，不保证获得所有景点与实时库存中的全局最优方案。

## 项目结构

- `TravelPlanner/config/`：项目配置与网址路由。
- `TravelPlanner/travel/`：数据查询、行程规划、预算核算等业务代码。
- `TravelPlanner/travel/templates/`：网页模板。
- `TravelPlanner/travel/static/`：样式、脚本与展示图片。
- `TravelPlanner/travel/migrations/`：数据库迁移文件。
- `TravelPlanner/travel/fixtures/`：初始化数据及测试资料。
- `TravelPlanner/deploy/`：云端启动与运行配置。
- `TravelPlanner/manage.py`：Django 管理入口。
- `TravelPlanner/Dockerfile`：Docker 构建配置。

## 运行与部署

本地运行需要安装 Python 依赖，并配置高德与途牛查询环境。途牛查询模块还需要 Node.js 和相应 CLI。

云端运行需要配置数据库、Django 密钥及接口密钥等环境变量。

详细部署说明见：
[Render 部署说明](TravelPlanner/README_RENDER.md)

请勿将真实 API Key、数据库密码或其他凭据提交到代码仓库。

## 数据与使用说明

- 接口报价、余票及库存会随查询时间变化。
- 部分费用采用估算方式，页面会说明其依据。
- 查询失败或数据不完整时，部分安排可能属于暂排方案。
- 酒店首晚参考价不代表全程同价或连续入住库存。
- 本系统提供旅行辅助规划，不提供支付、预订或出票服务。
- 实际出行前，请通过官方渠道确认开放时间、预约要求和最终价格。
